# Контекст проекта Narxoz College (NC)

> **Назначение файла:** сохранять актуальный контекст проекта после каждого создания, переписывания или редактирования. При новом чате — читать этот файл первым для быстрого ознакомления с проектом, условиями и текущим состоянием. Обновлять `context.md` после значимых изменений.

## 1. О проекте

**Название:** Narxoz College (NC) — веб-приложение для студентов и сотрудников колледжа.

**Целевая организация:** Колледж НАРХОЗ (Narxoz College), Казахстан.  
**Официальный сайт:** https://collegenarxoz.kz/

**Суть:** Единая платформа с журналом оценок, расписанием, форумом, заметками, событиями, профилями. Роли: Студент, Преподаватель, Директор, Админ. Адаптивный веб-интерфейс.

**Стек:**
- **Frontend:** веб-прототип (HTML/CSS/JS) в **`web/`** — http://localhost:8080/app/
- **Backend:** Go. Разрабатывается в **`cmd/api/`, `internal/`**.
- **БД:** PostgreSQL (любой SQL по ТЗ).

**Важно:** Официальной базы от колледжа пока нет — используется псевдо-база с тестовыми/реалистичными данными. Данные для сидинга можно брать с сайта колледжа (специальности, имена руководителей, факты).

**Репозиторий (GitHub):**  
https://github.com/q67q67q67-commits/college-system-app  
Клонирование: `git clone https://github.com/q67q67q67-commits/college-system-app.git`  
Рабочая ветка бэкенда: **Backend**. Код бэкенда пушится в эту ветку; слияние в main — через Pull Request.

**Go-модуль:** в `go.mod` и во всех импортах используется путь **`github.com/q67q67q67-commits/college-system-app`** (должен совпадать с URL репозитория; раньше был `github.com/narxoz-college/nc` — заменён во избежание ошибок `go get`).

## 2. Разделение ответственности: только Участник Б (Backend)

- **В этом репозитории выполняются только шаги Участника Б (Backend — Go + SQL).**
- **Участник Ф (Frontend — Flutter)** работает отдельно; к фронту не приступать в рамках бэкенд-задач.
- Чтобы избежать конфликтов и дублирования:
  - Б предоставляет стабильные API-эндпоинты, контракты (JSON), документацию (Swagger/список эндпоинтов).
  - Ф только потребляет API; не менять схему БД, не писать бэкенд-логику.
  - Все изменения контрактов API согласовывать и отражать в `context.md` и в `api/` (документация).

## 3. Роли и права (кратко)

| Роль в коде | Описание | Особенности |
|-------------|----------|-------------|
| `student` | Студент | Журнал, расписание, GPA, транскрипт, кредиты, форум, чаты, библиотека, файлы 2 ГБ, профиль. |
| `teacher` | Преподаватель | Учебная нагрузка: журнал, ДЗ, расписание, группы, библиотека; форум, чаты, события; профиль, файлы. |

- Доступ к аккаунту сохраняется до **1 года** после ухода из заведения (поле `users.left_at`).
- Музыка в приложении не предусмотрена (авторские права).

## 4. Фаза 1 — Участник Б (Backend). Чек-лист

Выполняются **только** эти шаги в рамках бэкенда.

1. **[Б] Инициализация окружения**
   - Корневая структура: `/cmd`, `/internal`, `/api`.
   - `docker-compose.yml` для PostgreSQL.
   - **Статус:** выполнено.

2. **[Б] Архитектура БД (SQL)**
   - Схема: `users` (с ролями), `groups`, `schedules`, `grades`, `forum_posts`, `library_books`, `events` (+ вспомогательные таблицы).
   - Поля для анонимности в форуме и лимитов хранилища (2 ГБ).
   - **Статус:** выполнено (`migrations/001_schema.sql`).

3. **[Б] Псевдо-база (Seeding)**
   - Скрипт заполнения: группы, студенты, преподаватели, директор.
   - **Статус:** выполнено (`migrations/002_seed.sql`). Пароль тестовых аккаунтов: `password123`.

4. **[Б] Система авторизации**
   - `POST /auth/login`.
   - Middleware проверки JWT по ролям (student, teacher, director, admin).
   - **Статус:** выполнено (`internal/auth`, middleware RequireAuth/RequireRole).

5. **[Б] Основной API (CRUD)**
   - Для студента: расписание, GPA, транскрипт, статус кредитов.
   - Для преподавателя: выставление оценок, управление ДЗ, список групп.
   - Библиотека: поиск книг, бронирование, указание владельца экземпляра.
   - **Статус:** выполнено (см. `api/ENDPOINTS.md`).

6. **[Б] Социум и файлы**
   - API форума (в т.ч. анонимные посты).
   - Чаты (WebSocket).
   - Сервис загрузки файлов с проверкой квоты 2 ГБ.
   - **Статус:** выполнено (форум, WebSocket `/api/chat/ws`, загрузка файлов, таблица `user_files`, миграция `003_user_files.sql`).

7. **[Б] Административные функции**
   - API добавления/редактирования новостей и событий (права: Админ, Директор).
   - **Статус:** выполнено (POST/PUT/DELETE /api/events, middleware RequireRole admin/director).

8. **[Б] Документация**
   - Swagger или список эндпоинтов с примерами JSON для фронтенда.
   - **Статус:** выполнено (`api/ENDPOINTS.md` — список эндпоинтов с примерами JSON).

9. **[Б] Веб-прототип (рабочий демо)**
   - Статика из папки `web/` раздаётся по пути `/app/` (см. `cmd/api/main.go`).
   - CORS включён для запросов к API с любого origin.
   - WebSocket-чат: токен передаётся в query-параметре `?token=...` (браузер не отправляет заголовки при апгрейде); в `internal/auth/middleware.go` добавлена поддержка `?token=...` для RequireAuth.
   - **Статус:** выполнено. Запуск: `go run ./cmd/api`, затем открыть **http://localhost:8080/app/**.
   - **Дизайн:** основная палитра (кроме белого и чёрного) — **#a82523**, **#d50032** (взяты с сайта университета НАРХОЗ: https://www.rk.narxoz.kz/ ).

10. **[Б] Профиль и директор**
   - **PUT /api/profile** — обновление пароля и/или телефона текущего пользователя (опциональные поля `password`, `phone`). Хендлер: `internal/handler/profile.go`, репозиторий: `UpdateUserPassword`, `UpdateUserPhone` в `internal/repository/user.go`.
   - **GET /api/director** — публичный профиль директора (без авторизации): `full_name`, `avatar_url`, `phone`, `email`. Для страницы «Профиль директора».
   - **Статус:** выполнено.

## 7. База данных (краткая выжимка)

- **PostgreSQL 16.** Подключение: пользователь `nc`, БД `nc_db`, пароль `nc_dev`, порт `5432`. Миграции из `migrations/` выполняются при первом запуске контейнера (`docker-entrypoint-initdb.d`).

**Основные таблицы:**

| Таблица | Назначение |
|--------|------------|
| `users` | Роль (`user_role`: student, teacher, director, admin), `storage_limit_bytes` = 2 ГБ, `storage_used_bytes`, `left_at`, язык. |
| `groups` | Учебные группы. |
| `user_groups` | Связь пользователь–группа (в т.ч. куратор). |
| `schedules` | Расписание (группа, преподаватель, предмет, день недели, время, аудитория). |
| `schedule_attachments` | ДЗ, уведомления, материалы к парам. |
| `grades` | Журнал оценок (студент, занятие, оценка, дата). |
| `forum_posts` | Посты форума: `is_anonymous`, `author_id` (для модерации при анонимности). |
| `library_books` | Книги (в т.ч. наличие физического экземпляра). |
| `library_copies` | Экземпляры, владелец, срок возврата. |
| `library_reservations` | Бронирование книг. |
| `events` | События/мероприятия (главная, лента). |
| `user_files` | Файлы пользователей (Мои файлы); триггер обновляет `users.storage_used_bytes`. |

**Важные правила:**
- Лимит хранилища: 2 ГБ = `2147483648` байт в `users.storage_limit_bytes`.
- Анонимность форума: `forum_posts.is_anonymous`; при `true` автор не отображается, `author_id` хранится для модерации.

Полная схема — в `migrations/001_schema.sql`.
