# Как запустить систему и проверить работоспособность

Пошаговая инструкция: от установки окружения до входа в систему и проверки по ролям.

---

## Что нужно заранее

- **Git** — для клонирования и веток.
- **Docker Desktop** (или Docker + Docker Compose) — для базы данных.
- **Go 1.22+** — для запуска API (скачать с [go.dev](https://go.dev/dl/)).
- **Браузер** — для веб-прототипа.
- **Ветка webPrototype:** только веб. Flutter не требуется.

---

## Шаг 1: Клонирование репозитория (если ещё не клонирован)

```bash
git clone https://github.com/q67q67q67-commits/college-system-app.git
cd college-system-app
```

Если репозиторий уже открыт в IDE — просто откройте терминал **в корне проекта** (там, где лежат `go.mod` и `docker-compose.yml`).

---

## Шаг 2: Запуск базы данных

В корне проекта выполните:

```bash
docker compose up -d
```

Проверка: контейнер с PostgreSQL должен быть запущен (порт 5432). При первом запуске автоматически применяются миграции из папки `migrations/` и заполняется тестовая база (сид).

---

## Шаг 3: Запуск API (бэкенд)

В том же терминале, в корне проекта:

```bash
go run ./cmd/api
```

Успех: в консоли строка вида **`api: listening on :8080`**.

- API доступен по адресу: **http://localhost:8080**
- Проверка в браузере: откройте http://localhost:8080 — должна отобразиться строка «NC API. Prototype: /app/».

Окно с `go run` не закрывайте — пока оно запущено, работает веб-прототип.

---

## Шаг 4: Веб-прототип (проверка в браузере)

1. Откройте в браузере: **http://localhost:8080/app/**
2. Должен открыться экран входа (поля «Email» и «Пароль»).

### Логины и пароли (для всех аккаунтов пароль один)

| Роль           | Email            | Пароль      |
|----------------|------------------|-------------|
| Студент        | student1@nc.kz   | password123 |
| Студент        | student2@nc.kz … student5@nc.kz | password123 |
| Преподаватель  | teacher1@nc.kz   | password123 |
| Преподаватель  | teacher2@nc.kz   | password123 |
| Директор       | director@nc.kz   | password123 |
| Админ          | admin@nc.kz      | password123 |

3. Введите, например: **student1@nc.kz** и **password123** → нажмите **«Войти»**.
4. После входа откроется главная страница с лентой событий; слева — меню (Главная, Расписание, Оценки, Группы, Форум, События, Мои заметки, Профиль директора, Регламент, Карта, Профиль).
5. Проверьте несколько разделов: **Расписание** (кнопка «ДЗ и материалы» у пар), **Оценки**, **Форум** (открытие темы и ответы), **Профиль** (смена пароля/телефона).
6. Нажмите **«Выйти»** в меню, затем войдите под **teacher1@nc.kz** / **password123** — в меню появятся пункты **«Группы»**, **«Выставить оценку»**, **«ДЗ к парам»**. Проверьте их.
7. Войдите под **director@nc.kz** или **admin@nc.kz** — на странице **«События»** должны быть кнопки **«Добавить»** и **«Удалить»** у событий. У **admin@nc.kz** в меню **нет** пункта «Профиль директора».

На узком экране (или при сужении окна) внизу появляется нижняя навигация вместо бокового меню.

## Шаг 5: Flutter (мобильная и веб-версия) — опционально

**Примечание:** В ветке **webPrototype** Flutter-приложение отсутствует. Этот шаг пропустить.

1. Установите Flutter по инструкции с [flutter.dev](https://flutter.dev/docs/get-started/install).
2. Убедитесь, что API и БД запущены (шаги 2 и 3).
3. В **новом** терминале перейдите в папку приложения и установите зависимости:

```bash
cd nc_app
flutter pub get
```

4. Запуск:
   - **Веб (Chrome):**  
     `flutter run -d chrome`
   - **Эмулятор Android:**  
     `flutter run -d android`  
     Если API запущен на ПК, а приложение в эмуляторе:  
     `flutter run -d android --dart-define=NC_API_URL=http://10.0.2.2:8080`
   - **Эмулятор iOS** (только на macOS):  
     `flutter run -d ios`

5. В открывшемся приложении войдите теми же данными, например **student1@nc.kz** / **password123**. Проверьте разделы (Главная, Расписание, Оценки, Библиотека, Форум, События, Файлы, Профиль директора, Регламент, Карта, Профиль). На широком экране — боковая панель, на узком — нижняя панель.

## Как добавить и запустить Android-эмулятор

Чтобы запускать Flutter-приложение на виртуальном устройстве Android:

### 1. Установить Android Studio (или только Android SDK)

- Скачайте [Android Studio](https://developer.android.com/studio) и установите.
- При первом запуске пройдите мастер настройки: он установит **Android SDK**, **SDK Platform-Tools** и **Android Emulator**.

Либо только командная строка (без Android Studio): [Command line tools](https://developer.android.com/studio/command-line) + установка пакетов через `sdkmanager`.

### 2. Включить виртуализацию (если эмулятор тормозит или не стартует)

- **Windows:** в BIOS/UEFI включите **Intel VT-x** или **AMD-V** (Virtualization Technology).
- Проверка: в диспетчере задач → «Производительность» → «ЦП» — должно быть «Виртуализация: Включено».

### 3. Указать Flutter путь к Android SDK (если нужно)

Если Flutter не находит Android:

```bash
# Windows (PowerShell) — подставьте свой путь к SDK
$env:ANDROID_HOME = "C:\Users\ВАШ_ПОЛЬЗОВАТЕЛЬ\AppData\Local\Android\Sdk"
# Или через «Настройки» → «Система» → «О системе» → «Переменные среды»: ANDROID_HOME = ...\Android\Sdk
```

### 4. Создать виртуальное устройство (AVD)

1. Откройте **Android Studio** → **More Actions** (или **Tools**) → **Device Manager** (ранее AVD Manager).
2. **Create Device** → выберите тип (например, **Phone** → **Pixel 6**) → **Next**.
3. Выберите образ системы (рекомендуется **API 34** или **API 33**; при необходимости нажмите **Download** рядом с образом) → **Next**.
4. Задайте имя AVD → **Finish**.

### 5. Проверить окружение и запустить эмулятор

В терминале:

```bash
flutter doctor
```

Убедитесь, что в разделе **Android toolchain** нет ошибок (при необходимости примите лицензии: `flutter doctor --android-licenses`).

Запуск эмулятора:

- **Из Android Studio:** в Device Manager нажмите ▶ рядом с нужным AVD.
- **Из терминала:**  
  `flutter emulators` — список эмуляторов,  
  `flutter emulators --launch <id>` — запуск по id (например, `flutter emulators --launch Pixel_6_API_34`).

Затем в папке **nc_app**:

```bash
flutter run -d android
```

Если приложение в эмуляторе не видит API на ПК:

```bash
flutter run -d android --dart-define=NC_API_URL=http://10.0.2.2:8080
```

(В эмуляторе Android `10.0.2.2` — это адрес вашего localhost.)

## Если что-то не работает

- **«Ошибка подключения» / нет данных после входа** — проверьте, что в отдельном терминале запущен `go run ./cmd/api` и в логе есть `listening on :8080`.
- **«invalid email or password»** — убедитесь, что БД поднята (`docker compose up -d`) и миграции с сидом применены (при первом `docker compose up -d` они применяются автоматически). Пароль везде: **password123**.
- **Flutter не видит API** — при запуске из эмулятора Android используйте `--dart-define=NC_API_URL=http://10.0.2.2:8080`.
- **Порт 8080 занят** — можно сменить порт API через переменную окружения: `set NC_ADDR=:8081` (Windows) или `export NC_ADDR=:8081` (Linux/macOS), затем снова `go run ./cmd/api`. Веб-прототип тогда открывать по адресу http://localhost:8081/app/.

## Как сохранить окончательный вариант в ветку main на GitHub

Ниже — как перенести текущий код (например, с ветки **FrontEndPart**) в **main** и считать main окончательной версией.

### Вариант A: Слияние через GitHub (рекомендуется)

1. Запушьте свою ветку (например, **FrontEndPart**) в GitHub:
   ```bash
   git add .
   git commit -m "Frontend: веб-прототип и Flutter, полный функционал по Заметке"
   git push origin FrontEndPart
   ```
2. Откройте репозиторий на GitHub: https://github.com/q67q67q67-commits/college-system-app
3. Переключитесь на ветку **FrontEndPart** (если ещё не выбрана).
4. Нажмите **«Pull request»** (или «Compare & pull request», если GitHub предложил после push).
5. В качестве **base** выберите ветку **main**, в качестве **compare** — **FrontEndPart**.
6. Опишите изменения и нажмите **«Create pull request»**.
7. Проверьте diff и нажмите **«Merge pull request»** → **«Confirm merge»**.
8. После слияния ветка **main** будет содержать окончательный вариант. При необходимости удалите ветку **FrontEndPart** в интерфейсе GitHub (опционально).

### Вариант B: Слияние локально и push в main

1. Убедитесь, что все изменения закоммичены и запушены в **FrontEndPart** (см. команды выше).
2. Переключитесь на **main** и подтяните последние изменения с GitHub (если main уже есть):
   ```bash
   git checkout main
   git pull origin main
   ```
   Если ветки **main** ещё нет локально:
   ```bash
   git fetch origin
   git checkout -b main origin/main
   ```
   Если на GitHub ветки main нет, можно создать её из текущей:
   ```bash
   git checkout -b main
   git push -u origin main
   ```
3. Слейте **FrontEndPart** в **main**:
   ```bash
   git merge FrontEndPart -m "Merge FrontEndPart: веб-прототип и Flutter, полный функционал"
   ```
4. Отправьте обновлённую **main** на GitHub:
   ```bash
   git push origin main
   ```
5. Теперь **main** на GitHub содержит окончательный вариант.

### После слияния в main

- Для дальнейшей работы можно продолжать в **main** или создать новую ветку от **main** (например, `git checkout -b develop`).
- Рекомендуется не коммитить напрямую в **main**, а делать изменения в отдельной ветке и сливать через Pull Request.
