# Туториал для фронтенд-разработчика (Narxoz College — NC)

Пошаговое руководство по Фазе 2: задачи Участника Ф (Frontend — Flutter). Бэкенд готов, API описан в **`api/ENDPOINTS.md`**. Используйте этот туториал вместе с контрактами API.

---

## Общие сведения

- **Стек:** Flutter (мобильная + веб, адаптация под ПК и смартфоны).
- **Базовый URL API:** `http://localhost:8080` (в проде — через конфиг/переменные окружения).
- **Авторизация:** после логина сохранять `token` из ответа и передавать в заголовке:  
  `Authorization: Bearer <token>`  
  При ответе 401 — перенаправлять на экран входа и очищать сохранённый токен.
- **Роли в ответе логина:** `student`, `teacher`, `director`, `admin`. От роли зависит набор экранов и доступ к кнопкам CRUD.
- **Тестовые аккаунты:** director@nc.kz, admin@nc.kz, teacher1@nc.kz, student1@nc.kz … student5@nc.kz. Пароль у всех: **password123**.

## Задача 9. Стартовый UI и навигация

**Цель:** настроить проект Flutter с адаптивной вёрсткой (Web/Mobile) и создать `MainScreen`, который переключает навигацию: Sidebar на Web и BottomNav на Mobile в зависимости от размера экрана.

### Шаги

1. **Создать проект Flutter** (если ещё не создан):
   ```bash
   flutter create nc_app
   cd nc_app
   ```
   Включить поддержку Web: `flutter config --enable-web` (если нужно).

2. **Определить breakpoint для «мобильный / десктоп»:**  
   Например, ширина экрана &lt; 600 px — мобильный (BottomNav), ≥ 600 px — десктоп (Sidebar). Использовать `MediaQuery.of(context).size.width` или пакет `responsive_builder` / аналог.

3. **Создать `MainScreen`:**
   - В состоянии хранить выбранный индекс/ключ текущего раздела (Главная, Учебный процесс, Социум, Профиль и т.д.).
   - На узком экране: нижняя навигационная панель (`BottomNavigationBar`) с иконками и подписями разделов.
   - На широком экране: боковая панель (`NavigationRail` или кастомный `Drawer`/Sidebar) с теми же разделами.
   - Центральная область: отображать виджет выбранного раздела (например, через `IndexedStack` или роут по ключу).

4. **Учесть роли:**  
   Набор пунктов навигации может зависеть от роли (студент: Главная, Учебный процесс, Социум, Профиль; преподаватель: Главная, Учебная нагрузка, Социум, Профиль; директор/админ — по ТЗ). Роль брать из сохранённых данных после логина (например, из ответа `/auth/login`).

5. **Проверить:** переключение размера окна (Web) или симуляция разных устройств — навигация меняется с BottomNav на Sidebar и обратно.

## Задача 10. Модуль Auth

**Цель:** экран входа, сохранение токена и данных пользователя, редирект на нужный дашборд в зависимости от роли.

### Шаги

1. **Экран входа (Login):**
   - Поля: email, пароль.
   - Кнопка «Войти». По нажатию: `POST /auth/login` с телом:
     ```json
     { "email": "...", "password": "..." }
     ```
   - При успехе (200): из ответа взять `token`, `user_id`, `role`, `email`, `full_name`, `expires_at` и сохранить локально (например, `shared_preferences` или `flutter_secure_storage`). Токен — для заголовка `Authorization: Bearer <token>` во всех дальнейших запросах.
   - При 401: показать сообщение «Неверный email или пароль».

2. **Сохранение токена и профиля:**
   - Сохранять: `token`, `user_id`, `role`, `email`, `full_name` (и при необходимости `expires_at`). При старте приложения проверять наличие токена; если есть — считать пользователя авторизованным и переходить на MainScreen (или на главную дашборда).

3. **Редирект по роли:**
   - После логина (или при открытии приложения с уже сохранённым токеном) открывать один и тот же `MainScreen`, но набор пунктов меню и доступные экраны определять по полю `role`:
     - `student` → Главная, Учебный процесс, Социум, Профиль.
     - `teacher` → Главная, Учебная нагрузка, Социум, Профиль.
     - `director` → как у преподавателя + CRUD новостей/событий, профиль директора как «Twitter».
     - `admin` → как у директора, но без страницы профиля директора; админ-панель.

4. **Выход:** кнопка «Выйти» очищает сохранённый токен и данные пользователя и перенаправляет на экран входа.

5. **Обработка 401:** при любом запросе к API, если ответ 401, очистить токен и перенаправить на экран входа.

## Задача 11. Главный экран (Новости)

**Цель:** лента новостей и мероприятий с поиском по дате/словам; для ролей Директор и Админ — кнопки добавления, редактирования и удаления.

### Шаги

1. **Получение списка событий/новостей:**  
   `GET /api/events?from=...&to=...&q=...&limit=20&offset=0`  
   Параметры: `from`, `to` — даты в формате YYYY-MM-DD (опционально), `q` — строка поиска, `limit`, `offset` — пагинация. В заголовок добавить `Authorization: Bearer <token>`.

2. **Отображение:**  
   Список карточек: заголовок (`title`), описание (`description`), фото (`image_url`, если есть), дата (`event_date`), место (`location`). Все данные приходят с главной страницы — открытие в отдельной странице не обязательно по ТЗ, но можно сделать по клику для детального просмотра через `GET /api/events/{id}`.

3. **Поиск:**  
   Поле ввода для текста (`q`) и при необходимости выбор диапазона дат (`from`, `to`). При изменении фильтров — повторный запрос `GET /api/events` с новыми параметрами.

4. **CRUD для Директор и Админ:**  
   Показывать кнопки «Добавить», «Редактировать», «Удалить» только если `role` равен `director` или `admin`.
   - **Добавить:** форма с полями title, description, image_url, event_date, location. Отправка: `POST /api/events` с JSON-телом (см. `api/ENDPOINTS.md`). После успеха — обновить список.
   - **Редактировать:** форма с теми же полями, предзаполненная данными события. Отправка: `PUT /api/events/{id}`. После успеха — обновить список.
   - **Удалить:** подтверждение, затем `DELETE /api/events/{id}`. После успеха — убрать элемент из списка или обновить список.

## Задача 12. Учебный процесс (по ролям)

**Цель:** для студента — вкладки Журнал, Расписание, GPA, Регламент, Библиотека; для преподавателя — интерфейс выставления оценок, просмотр групп, управление нагрузкой (ДЗ).

### Студент

1. **Журнал оценок:**  
   `GET /api/grades` — список оценок текущего пользователя. Отображать в виде списка/таблицы: предмет (`subject`), оценка (`grade`), дата (`grade_date`), комментарий (`comment`).

2. **GPA:**  
   `GET /api/grades/gpa` — ответ `{"gpa": 87.75}`. Показать на отдельной карточке или в шапке раздела «Журнал».

3. **Транскрипт:**  
   `GET /api/grades/transcript` — тот же формат, что и журнал (список оценок с датами и предметами). Можно оформить как отдельную вкладку или объединить с журналом.

4. **Расписание:**  
   `GET /api/schedule` — список занятий (день недели, время, предмет, аудитория, преподаватель id). Отображать по дням недели. Для каждой пары можно запрашивать дополнения: `GET /api/schedule/{id}/attachments` (ДЗ, уведомления).

5. **Регламент обучения:**  
   Академический календарь и силлабус — по ТЗ «регламент с прикреплённым силлабусом». Бэкенд может не отдавать отдельный API для календаря; можно сделать статичную страницу или позже добавить эндпоинт. Пока — заглушка или локальный контент.

6. **Библиотека:**  
   - Поиск книг: `GET /api/library/books?q=...&limit=20`. Показывать список: название, автор, наличие (available), есть ли физический экземпляр.
   - Детали книги / экземпляры: `GET /api/library/books/{id}/copies` — кто взял книгу, срок возврата.
   - Бронирование: форма/кнопка «Забронировать» → `POST /api/library/reservations` с `book_id` и при необходимости `expires_at`.

### Преподаватель

1. **Список групп:**  
   `GET /api/groups` — группы с количеством студентов. По клику на группу: `GET /api/groups/{id}/students` — список студентов группы.

2. **Выставление оценок:**  
   - Выбор студента (из списка группы) и занятия (из расписания преподавателя).  
   - Добавить оценку: `POST /api/grades` с телом `user_id`, `schedule_id`, `grade`, `grade_date`, `comment`.  
   - Редактировать: `PUT /api/grades/{id}` с `grade`, `comment`.  
   - Удалить: `DELETE /api/grades/{id}`.

3. **Управление ДЗ (дополнения к парам):**  
   - Список занятий: из `GET /api/schedule` (для преподавателя вернётся его расписание).  
   - По занятию: `GET /api/schedule/{id}/attachments` — список ДЗ/уведомлений.  
   - Добавить: `POST /api/schedule/{id}/attachments` с `title`, `body`, `attachment_type` (homework, notification, material).  
   - Редактировать: `PUT /api/attachments/{id}` с `title`, `body`.  
   - Удалить: `DELETE /api/attachments/{id}`.

4. **Расписание и градация оценок:**  
   Расписание — тот же `GET /api/schedule`. Градация — отображение правил оценивания (при необходимости статичная страница или отдельный API в будущем).

## Задача 13. Модуль Социум

**Цель:** экран форума (с переключателем «Анонимно»), чат-интерфейс (общий, при необходимости личные/групповые), интерактивная карта здания, лента событий с комментариями.

### Форум

1. **Список тем (корневые посты):**  
   `GET /api/forum/posts?limit=20&offset=0` (без `parent_id`). Отображать карточки: заголовок (`title`), начало текста (`body`), дата, автор (если не анонимно — `author_name`; при `is_anonymous: true` автора не показывать).

2. **Открытие темы (ответы):**  
   `GET /api/forum/posts?parent_id={id}&limit=20&offset=0` — ответы к теме. Отображать вложенно или списком под темой.

3. **Создание темы или ответа:**  
   Форма: заголовок (для темы), текст, **переключатель «Публиковать анонимно»** (`is_anonymous`).  
   Отправка: `POST /api/forum/posts` с телом `parent_id` (null для темы, id темы для ответа), `is_anonymous`, `title`, `body`.  
   При анонимном посте не отображать имя автора в UI (бэкенд всё равно хранит author_id для модерации).

### Чаты

1. **Общий чат (WebSocket):**  
   Подключение: `GET /api/chat/ws` с заголовком `Authorization: Bearer <token>` (HTTP-запрос апгрейдится до WebSocket).  
   После подключения отправлять/получать сообщения в формате JSON, например `{"type":"message","body":"текст"}`. Сервер рассылает каждое сообщение всем подключённым — отображать в общем ленте чата.

2. **Личные и групповые чаты:**  
   В текущем API реализован только общий чат (один WebSocket hub). Личные и групповые чаты требуют доработки бэкенда (комнаты, таблицы сообщений). На фронте можно заложить экран «Чаты» с вкладкой «Общий чат» и заглушками для «Личные»/«Групповые» до появления API.

### Карта здания

Интерактивная карта для эвакуации/навигации — статичный контент или отдельный ресурс (изображение, PDF). Бэкенд не обязан отдавать карту; достаточно экрана с загрузкой карты из assets или URL.

### Лента событий с комментариями

События уже отображаются на главной (`GET /api/events`). «Лента событий с комментариями» по ТЗ может означать: под каждым событием блок комментариев. Сейчас API событий не включает комментарии; можно добавить заглушку «Комментарии» под карточкой события или договориться с бэкендом о новом эндпоинте (например, комментарии к событию). Пока — отображать ленту событий и при необходимости статичный текст «Комментарии будут доступны позже».

## Задача 14. Профили и файлы

**Цель:** обычный профиль (данные, смена пароля, язык), «Мои файлы» (облачное хранилище с папками, лимит 2 ГБ), профиль директора в стиле «Twitter-аккаунт» с закреплёнными постами.

### Обычный профиль (все роли, кроме отдельного экрана директора)

1. **Данные пользователя:**  
   Отображать сохранённые после логина: имя (`full_name`), email, роль. Смена пароля/номера телефона: отдельного API в текущем списке нет — либо заглушка «Скоро», либо запрос к бэкенду на добавление эндпоинта (например, `PUT /api/profile` с полями password, phone).

2. **Язык интерфейса:**  
   Локальное переключение (локализация Flutter), без обязательного запроса к API (в БД у пользователя есть поле `language` — при появлении API синхронизации можно сохранять выбор на бэкенде).

3. **Выход:**  
   Очистить токен и данные пользователя, переход на экран входа.

### Мои файлы

1. **Список файлов и квота:**  
   `GET /api/files` — в ответе `files` (список файлов с id, path, filename, size_bytes, content_type), `storage_limit`, `storage_used`. Показать использование: например, «X МБ из 2 ГБ».

2. **Загрузка файла:**  
   `POST /api/files/upload` — multipart/form-data, поле `file`. При ответе 403 и тексте про квоту — показать сообщение «Превышен лимит хранилища (2 ГБ)».

3. **Удаление файла:**  
   `DELETE /api/files/{id}` — по id из списка файлов. После успеха обновить список и квоту.

4. **Папки и портфолио:**  
   Текущий API отдаёт плоский список файлов с путём `path`. Организацию в «папки» и «поделиться как портфолио» можно имитировать на фронте (группировка по префиксу path или тегам), либо дождаться расширения API (папки, шаринг). Пока — список файлов и загрузка/удаление с отображением квоты.

### Профиль директора (роль director)

Отображать как публичный «Twitter-аккаунт»: шапка (обложка), фото профиля, имя, описание, посты (фото/видео), возможность закреплять посты, кнопка «Написать директору». Данные директора можно брать из текущего пользователя, если вошёл директор, или запросить отдельный эндпоинт «профиль директора» (если бэкенд его добавит). Посты директора и закреплённые — при наличии соответствующего API; иначе заглушка с текстом и аватаром. Кнопка «Написать директору» — переход в чат или форму (при появлении личных чатов — в чат с директором).

**Админ:** по ТЗ без страницы профиля директора — у роли `admin` не показывать этот блок «профиль директора», только админ-панель и CRUD событий.

## Задача 15. Финализация

**Цель:** тестирование всех ролей и проверка адаптации под ПК и смартфоны.

### Шаги

1. **Проверить под каждой ролью:**  
   Войти как student, teacher, director, admin (тестовые аккаунты из `context.md`). Убедиться, что отображаются правильные пункты меню и экраны, кнопки CRUD видны только там, где разрешено (события — director/admin; оценки и ДЗ — teacher/director/admin).

## Краткая шпаргалка по API

| Действие | Метод и путь | Заголовки |
|----------|----------------|-----------|
| Вход | POST /auth/login | — |
| Расписание | GET /api/schedule | Authorization: Bearer &lt;token&gt; |
| Оценки | GET /api/grades, GET /api/grades/gpa, GET /api/grades/transcript | то же |

| Чат | GET /api/chat/ws (WebSocket) | Authorization: Bearer &lt;token&gt; при апгрейде |
| ДЗ (преподаватель) | GET /api/schedule/{id}/attachments, POST /api/schedule/{id}/attachments, PUT/DELETE /api/attachments/{id} | то же |
| Оценки (преподаватель) | POST /api/grades, PUT/DELETE /api/grades/{id} | то же |

Полные примеры тел запросов и ответов — в **`api/ENDPOINTS.md`**.
